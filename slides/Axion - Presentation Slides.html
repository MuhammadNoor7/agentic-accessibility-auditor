01 — Opening Statement

Accessibility review doesn’t scale like the apps it’s reviewing.

Manual walkthroughs are slow. Screenshot-only scanners are blind to anything that isn’t a pixel. Both leave a developer with a code and no explanation.

MANUAL

Screen-reader walkthroughs and checklists — one reviewer, one screen, at a time.

PARTIAL

Content-desc, focus order, touch-target math — encoded in the hierarchy, invisible to a pixel-only scan.

SILENT

A raw diagnostic code, with no account of why it matters or how to fix it.

02 — Position Taken

The rule engine detects. The model only explains.

A rendered screenshot plus its UIAutomator XML — the same tree Android’s own TalkBack reads — parsed once, checked deterministically. Recent tools like ScreenAudit and Insight put an LLM directly in the detector’s seat — we took the opposite position.

Screenshot-first tools
LLM looks directly at the screenshot
↓
LLM decides what counts as a violation
Not reproducible · can invent findings
Axion
Rule engine parses screenshot + XML
↓
Rule engine decides — deterministic, no ML in the loop
↓
LLM only explains — checked against a real violation ID
Same input → same output, every time

06 — The Rule Engine

30 rules, mapped to 30 WCAG-aligned guidelines, one deterministic pass.

R01Clickable with empty text and empty content-descHighG01
R02Image button, clickable, empty content-descHighG02
R04Clickable width or height under 48dpHighG04
R05EditText with empty hint, text, and content-descHighG05
R08Bounding-box overlap over 50% of the smaller elementMedG08
R09Declared contrast under 4.5:1 text / 3:1 iconsMedG09

Pure Python, no ML dependency. Identical input → identical output — which is what made regression-testing 7,068 screens actually tractable.

15 — Filed Without Redaction

Said plainly, not buried in an appendix.

Data coverage

R09, R10, R28, and R29 are correctly implemented but structurally inactive — neither dataset ever declares raw color or text-size attributes.

CV modules

Both generalize for real, but modestly (macro-F1 0.22, mAP50 0.25). They confirm the rule engine — they never override it.

Prototype scope

A flat JSON store and JWT auth, by design — an eight-week research prototype, not a production system.
